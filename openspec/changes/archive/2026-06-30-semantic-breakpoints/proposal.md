## Why

The project uses Tailwind v4's default breakpoint prefixes (`sm:`, `md:`, `lg:`, `xl:`, `2xl:`) — abstract names that don't communicate which device tier they target. Reading `md:grid-cols-3` requires memorizing that `md` = 768px = tablet. Replacing them with semantic names (`mobile:`, `tablet:`, `desktop:`) makes responsive intent immediately readable in markup: `tablet:grid-cols-3` is self-documenting. Tailwind v4 supports custom breakpoint names via `--breakpoint-*` tokens in `@theme`, so this is a configuration change, not a fork.

## What Changes

- **BREAKING**: Remove Tailwind v4's default breakpoint tokens (`sm`, `md`, `lg`, `xl`, `2xl`) from the generated utility set by setting `--breakpoint-*: initial` in `@theme` in `src/routes/layout.css`. After this change, `sm:`/`md:`/`lg:`/`xl:`/`2xl:` variants will NO LONGER be generated by Tailwind. Any code (including future shadcn-svelte additions) that uses these prefixes will silently produce no styles.
- Add three semantic breakpoint tokens to `@theme`: `--breakpoint-mobile: 40rem` (640px), `--breakpoint-tablet: 48rem` (768px), `--breakpoint-desktop: 64rem` (1024px). These generate `mobile:`/`tablet:`/`desktop:` variant prefixes.
- Replace all 18 responsive-prefix usages in 2 source files: `sm:` → `mobile:` (1×), `md:` → `tablet:` (14×), `lg:` → `desktop:` (4×). Files: `src/routes/+page.svelte` (15 occurrences), `src/routes/events/[slug]/+page.svelte` (3 occurrences).
- Update spec text in 4 capabilities that reference old prefix names in requirement bodies and scenarios.
- Document the new breakpoint convention in `AGENTS.md`.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `landing-page`: The "Layout is responsive" requirement and the section/composition requirements that reference `md:`/`lg:`/`sm:` prefixes SHALL be updated to use `mobile:`/`tablet:`/`desktop:` names. A new requirement SHALL document the `@theme` breakpoint token definitions.
- `landing-stitch`: Spec text that references `md:grid-cols-*`, `lg` breakpoint, `sm:grid-cols-*` in requirement bodies and scenarios SHALL be updated to the new semantic names.
- `shadcn-components`: Card variant requirement examples that reference `md:col-span-*` SHALL be updated to `tablet:col-span-*`.
- `stitch-100pct`: Bento grid and partners grid scenario text that references `md:grid-cols-*`, `md:h-[600px]`, `sm:grid-cols-*` SHALL be updated to the new semantic names.

## Impact

- **Affected code**: `src/routes/layout.css` (add/remove `--breakpoint-*` tokens in `@theme`), `src/routes/+page.svelte` (15 class-string edits), `src/routes/events/[slug]/+page.svelte` (3 class-string edits). No structural/JS changes.
- **Affected specs**: `openspec/specs/landing-page/spec.md`, `openspec/specs/landing-stitch/spec.md`, `openspec/specs/shadcn-components/spec.md`, `openspec/specs/stitch-100pct/spec.md` — spec text updated to use new prefix names.
- **Affected docs**: `AGENTS.md` — add a "Breakpoints" note documenting the semantic naming convention and the removal of defaults.
- **No new dependencies.** No changes to `package.json`, `vite.config.ts`, or `components.json`.
- **Risk**: Any future `pnpm dlx shadcn-svelte add <component>` that imports a component using `sm:`/`md:`/`lg:` internally would silently lose responsive styles. Mitigation: the project's shadcn components (Card, Button, Separator, NavigationMenu) were audited and none use responsive breakpoint prefixes in their `.svelte` files. Future shadcn additions should be checked.
- **tailwind-variants `.style.ts` files**: NOT affected. The `sm`/`md`/`lg`/`xl` strings in `button.style.ts`, `input.style.ts`, `badge.style.ts`, `avatar.style.ts`, `checkbox.style.ts` are `size` variant keys (object property names in `tv()` configs), not responsive breakpoint prefixes. They do not interact with `--breakpoint-*` tokens.
