## Why

The `align-stitch-landing` change brought the homepage to ~95% visual match with the Stitch design at `projects/15775088065885956423/screens/201e2a86b11f4749a57a6d6ab46caff2`, but inspection of the rendered HTML via headless Chromium reveals that all the typography tokens (`text-headline-xl`, `text-headline-lg`, `text-headline-md`, `text-body-lg`, `text-body-md`, `text-label-lg`, `text-label-md`) used in the Stitch HTML are not generating in Tailwind v4 because the project's `@theme` block defines different token names (`--text-display`, `--text-headline`, `--text-title`, `--text-body`, `--text-label`). The fallback is 16px across the board — the hero `<h1>` is rendered at 16px, the Empower CTA `<h2>` is rendered at 16px, the event-card `<h3>` is rendered at 16px, and the section `<h2>` headings are rendered at 16px. The visual layout, colors, and component composition are correct; the typography is collapsed to body size, which is what makes the page "not 100% match" to the Stitch source. The Stitch HTML is now committed at `tmp/index.html` (30KB, 444 lines, fetched live from `get_screen`); the goal is to lift its tailwind config into the project's design system verbatim and rewrite the homepage so the rendered output is byte-equivalent to the Stitch HTML (with the brand "PKUBersua" substituted for "Pekanbaru Community" and four placeholder partner logos for the third-party brand logos).

## What Changes

- **Lift the Stitch tailwind config verbatim into `src/routes/layout.css`.** Add the seven missing text-size tokens (`--text-headline-xl: 48px / 56px line-height / -0.02em letter-spacing / 800 weight`, `--text-headline-lg: 32px / 40px / 600`, `--text-headline-md: 24px / 32px / 600`, `--text-body-lg: 18px / 28px / 400`, `--text-body-md: 16px / 24px / 400`, `--text-label-lg: 14px / 20px / 0.05em / 600`, `--text-label-md: 12px / 16px / 500`) and the three missing color tokens (`--color-inverse-primary: #e7c268`, `--color-on-primary-fixed: #251a00`, `--color-on-primary-fixed-variant: #5a4400`) so that `text-headline-xl`, `text-headline-lg`, `text-headline-md`, `text-body-lg`, `text-body-md`, `text-label-lg`, `text-label-md` all generate as Tailwind utilities with the Stitch sizes.
- **Rewrite the homepage** in `src/routes/+page.svelte` as a byte-for-byte translation of the Stitch HTML at `tmp/index.html`. The structure is: header (h-20 sticky, 4 nav links, search bar, Login/Register pill) → hero (h-870px, batik pattern, bg image, hero-clip, dual CTAs) → events grid (3-col, Stitch-style card) → bento news grid (4-tile mosaic) → Empower Your Business CTA (rounded-3xl gold card) → Trusted by Partners (4-logo grid) → footer 4-col with email input. **BREAKING** for the previous composition: the "Event Sebelumnya" section is removed (Stitch has no past-events listing), the bento news grid is added (was previously skipped), the partner logos are now the four third-party brand logos from Stitch.
- **Replace the four placeholder partner logos** in `static/partners/` with the four Stitch third-party logos. The Stitch HTML has `<img alt="Pekanbaru City Logo" src="...">`, `<img alt="Bank Riau Kepri Syariah Logo" src="...">`, `<img alt="Visit Riau Logo" src="...">`, `<img alt="Wonderful Indonesia Logo" src="...">`. These are downloaded as `static/partners/logo-{1,2,3,4}.svg` (the `.svg` is the same screenshot URL re-rendered as inline SVG with `currentColor` so the grayscale hover effect works).
- **Replace the dummy events** in `src/lib/features/events/services/dummy-events.ts` with the three events from the Stitch HTML (`Traditional Talam Masterclass`, `Riau Heritage Night`, `Local Business Mixer`), keeping the existing `category` / `categoryLabel` / `categorySecondary` fields. Past events remain for the event detail page.
- **Use Stitch's exact class names verbatim in the Svelte markup.** Where the project has a reusable component that matches (e.g., the `EventCard`), the component is reused with the Stitch classes applied; where a reusable component does not exist (e.g., the bento tile, the Empower CTA, the partner logo tile, the header), the Stitch HTML is translated 1:1 with the class names force-applied via `class={...}` to defeat Tailwind's class-merging and ensure the literal Stitch classes render.

## Capabilities

### New Capabilities

- `stitch-100pct`: The byte-for-byte translation of the Stitch HTML at `tmp/index.html` to Svelte 5 + Tailwind v4. Covers the seven new text-size tokens, the three new color tokens, the homepage composition (header / hero / events / bento / Empower CTA / Trusted by Partners / 4-col footer), the four third-party partner logos (downloaded to `static/partners/`), the three Stitch event cards (downloaded as the new dummy data), and the rule that any Stitch class name SHALL be applied verbatim via `class={...}` to defeat class merging.

### Modified Capabilities

- `brand-pkubersua`: The existing `brand-pkubersua` spec's "Design token system is the Stitch Material-3 golden palette" requirement is REPLACED with a more specific "Stitch font-size and color tokens are defined as compound values matching `tmp/index.html`" requirement. The new spec lists each of the seven text-size tokens with their exact values.
- `events`: The existing `events` spec's "Event data shape is the Event type" requirement is REPLACED with a more specific requirement that the dummy data SHALL contain exactly three events (matching the Stitch HTML) and the `category` enum SHALL map 1:1 to the Stitch event card pill text.
- `landing-stitch`: The existing `landing-stitch` spec's "Hero is a fixed 870px section with batik pattern, hero-clip, and dual CTAs" and "Upcoming Community Gatherings is a 3-column event grid" and "Empower Your Business CTA section" and "Trusted by Partners is a 4-logo grid with grayscale hover" and "Footer is a 4-column layout with email input" requirements are RETIRED. They are replaced by a single new requirement that the homepage SHALL be a byte-for-byte translation of `tmp/index.html` (with brand substitution for "Pekanbaru Community" → "PKUBersua" and three of the four partner logos replaced with placeholders if the user requests).
- `landing-page`: The existing `landing-page` spec is REPLACED in its entirety with a single requirement that the homepage composition is the Stitch composition (header / hero / events / bento / Empower CTA / Trusted by Partners / footer), with the section names inherited from the Stitch HTML (`Upcoming Community Gatherings`, `Latest News & Stories`, `Empower Your Business Through Community`, `Trusted by Local & Global Partners`).
